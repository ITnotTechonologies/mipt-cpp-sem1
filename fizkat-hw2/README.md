# ФизКат

Консольный учёт прокатной техники и вещей. Каждая команда занимает одну строку.
Инвентарный номер уникален, номер и имя вводятся без пробелов.

## Сборка на Fedora

Из каталога с исходниками:

- Компиляция проекта
```sh
g++ -std=c++17 -Wall -Wextra -Werror -pedantic main.cpp fleet.cpp inventory.cpp -o fizkat
```
- Запуск программы
```sh
./fizkat
```

## Команды

| Ввод | Результат |
| --- | --- |
| `add scooter id name energy score`, `add ebike id name energy score` | Принять электросамокат или электровелосипед после техосмотра |
| `add bike id name score` | Принять обычный велосипед после техосмотра |
| `add dock id name energy` | Добавить док-станцию |
| `add helmet id name`, `add lock id name` | Добавить шлем или велозамок |
| `list` | Вывести все позиции в формате `id name` по возрастанию номера как строки |
| `novice`, `count_novice` | Вывести подходящую новичкам технику или её количество |
| `energy` | Вывести суммарный расход за сутки в кВт·ч с одним знаком после точки |
| `report` | Вывести количество позиций и суммарный расход через пробел |
| `focus id`, `show_focus` | Выбрать позицию для витрины или показать выбор |
| `remove id` | Снять позицию с баланса |
| `quit` | Завершить работу. Конец входного файла также завершает программу |

Расход задаётся конечным неотрицательным числом, простота — целым от 1 до 10.
Техника с простотой от 6 включительно доступна новичкам. При техосмотре
подстрока `broken` в имени транспорта в любом регистре означает отказ.
Вещи техосмотр не проходят. Велозамок и отчёт `count_novice` — дополнения
к базовому набору.

## Устройство

В [inventory.hpp](inventory.hpp) стрелка ниже направлена от базового класса
к производному. У `ElectricTransport` и `Dock` по два базовых класса.
Общего предка у их двух ветвей нет, виртуальное наследование не требуется.

```text
InventoryItem → Item → Transport → Bike
                                 → ElectricTransport → Scooter, ElectricBike
                     → Helmet, Dock, BikeLock
EnergyConsumer → PowerUse → ElectricTransport, Dock
```

Оператор вывода вызывает виртуальный `Describe`, а отбор для новичков —
виртуальный `ForNovice`. При подсчёте энергии парк запрашивает интерфейс
`EnergyConsumer` и вызывает `DailyEnergy`. Добавление нового потребителя
не требует изменений в отчёте.

Шаблон `Registry<T>` в [fleet.hpp](fleet.hpp) хранит объекты по порядку
номеров. При вставке он использует `operator<` и проверяет совпадение номера
через `operator==`. Поэтому список готов к печати сразу после добавления.
Шаблон `ReadNumber<T>` в [main.cpp](main.cpp) разбирает и целые оценки,
и вещественный расход, проверяя, что число занимает весь аргумент.

В реестре каждая позиция принадлежит одному `unique_ptr<InventoryItem>`.
Транспорт одного вида разделяет неизменяемую спецификацию `ModelSpec` через
`shared_ptr`: в ней заданы вид и порог для новичков. Витрина хранит
`weak_ptr` на карточку конкретной позиции. При удалении позиции карточка
освобождается, и `show_focus` печатает `expired`. Повторное добавление
того же номера не переключает витрину на новый объект.

У исключений общий базис `FleetError`. `InspectionError` означает отказ
техосмотра. `CommandError` обозначает ошибку ввода, повторный номер
или обращение к отсутствующей позиции. Команда проверяется целиком до изменения
парка. Сообщение с префиксом `error:` выводится в `main`, затем можно
ввести следующую команду.

## Проверка

После сборки запустить из того же каталога:

```sh
python3 tests/test_cli.py
```

Тесты подают команды в стандартный ввод и сверяют вывод построчно. Проверяются
пример из задания, порядок номеров, границы шкалы, отчёты, отказ техосмотра,
срок жизни витрины и сохранение состояния после ошибочной команды.
